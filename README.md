## 0.5.5 后台更新提示

插件挂载后会在后台静默检查一次，无需展开 WebDAV 面板；发现仓库版本或前端提交更新时，在插件块顶部显示常驻提示。提示包含“更新”和关闭按钮；关闭只持续到当前页面刷新，不会更新代码。更新仍需用户确认，且仍要求核验安装来源、后端锁定；结束后必须重启 Luker 并重新加载页面。网络不可用时不弹打扰提示，可在面板里手动重试。

0.5.3 保留原始传输错误码，在失败任务详情中显示请求耗时、送入请求流的字节数、请求体是否发送完、响应状态和是否复用连接。用于定位包括 Koofr 在内的 WebDAV 上传中断；这是错误处理与诊断改进，尚不代表 Koofr 大备份断线已经解决。诊断不含认证信息、远端 IP 或原始响应头。仍不自动重传、不支持断点续传。


调用 Luker 内置分类备份接口，边生成 ZIP 边上传到 WebDAV，不创建完整的本地 ZIP。支持自动建目录、云端列表、大小复核与操作通知。恢复使用 Luker 自身功能。

## 0.5.5 密码与更新面板

已保存的应用密码默认显示遮罩。点击眼睛，通过管理员专用、禁止缓存的接口取得真实密码并显示；再点隐藏。隐藏已保存密码、收起面板或切后台会移除已取回的明文，未保存的新输入只切回密码类型，不丢失编辑。遮罩不是加密，也不代表密码长度；未改密码时保存不会提交遮罩。用户确实输入八个星号会按新密码保存。

版本面板显示当前运行的前端和后端版本，不一致时提示。首次成功读取配置后自动检查一次，可手动再次检查（间隔至少15秒）。检查访问固定GitHub版本清单和宿主安装列表；不会自动更新。

“更新前后端”先核实当前前端目录、实际运行后端目录和两端Git来源，必须均为 `Aouky7/webdav_luker`。用户确认后先更新服务端插件，再更新前端扩展。支持Git安装且宿主提供相应接口；旧仓库、手动ZIP安装或无法识别的目录需先在宿主管理中处理。本功能不会安装其他插件、修改远端来源、安装依赖、自动强制覆盖或自动重启。

这是两个顺序操作，不是事务。部分失败和网络结果未知会分别显示，不能自动回滚或重复执行。代码下载成功后仍显示当前运行版本，必须手动重启后端、重新加载页面才生效。更新期间后端锁住新备份、配置保存和连接测试；成功/结果不明时保留锁直至后端重启，明确失败且未更新成功时才释放。刷新页面不能替代重启。

前端需新增 `updates.js`，否则模块加载失败。第一次升级到0.5.4仍按原方式更新两端；新按钮用于后续更新。源码接口已核对、离线测试已覆盖，当前尚未在你的Luker上执行真实联合更新。

## 安装与更新

仓库：<https://github.com/Aouky7/webdav_luker>

同一仓库分别安装为服务端插件和前端扩展。更新后重启 Luker 后端、重新加载页面，确认两端为 0.5.5。

- 后端需要 `index.mjs`、`webdav.mjs`。
- 前端需要 `frontend.js`、`updates.js`、`style.css`、`manifest.json`。
- 运行不需要第三方 npm 依赖；jsdom 仅用于开发测试。
- 旧版 `staging.mjs` 和 `tests/staging.test.mjs` 已从本版移除。手动覆盖安装时残留模块不会被加载，可移除这两个旧源码文件。
- 本版不再初始化、扫描或删除旧版运行时暂存目录。若曾成功打包后异常退出，残留 ZIP 需先核实路径和内容再自行清理，不能删除整个系统临时目录。

接口仅允许当前 Luker 管理员使用。具体入口、归档范围和恢复能力取决于宿主版本。

## WebDAV 配置

填写最终 HTTPS WebDAV 目录地址、用户名和密码（服务商要求时使用应用密码）。支持 Basic 认证，不跟随重定向，不关闭证书验证。

服务需支持 PROPFIND、未知长度 PUT、MOVE；缺失目录需要 MKCOL 创建权限，HEAD 仅作为大小查询后备。单次上传最多 30 分钟，网络空闲时限 2 分钟。

保存配置仅保存设置。测试连接或开始备份时自动确认目录，创建明确不存在的目标及中间目录；最多 12 层，总准备时限 60 秒。权限不足、目标是文件或状态不明时不进入上传。可能保留已经创建的空目录。

坚果云推荐 `https://dav.jianguoyun.com/dav/LukerBackup/`。只填 `/dav/` 时保存会规范到 `/dav/LukerBackup/`；不会向 `/dav/` 以上探测或创建。测试连接不验证上传/改名权限。

## 日常使用

1. 结束聊天生成和编辑，选好分类并保存配置。
2. 点击备份并核对目标及分类。
3. 保持后端运行，等待上传、改名与大小核对完成。
4. 手动刷新云端列表，必要时复核最近一次备份大小。

已发送字节是送入上传流的字节数，不代表远端已持久化，也不是总进度。先写 `.partial`，成功后 MOVE 为 `.zip`。改名结果不明时，两种名称都可能存在，须另行核验。写入失败不自动重放。

HTTP 411 表示服务要求预知长度，当前流式模式不兼容；413 是服务/代理大小限制；507 是云端空间不足。所有模式选择与本地打包提示已经移除。

保存、测试、重新读取、列表、核验有通知和面板反馈。初次打开不播报旧结果；观察到的任务终态只通知一次。状态查询失败不等于备份失败。收起面板仍跟踪任务，隐藏页面暂停查询，重新显示恢复；这不是 Android 系统通知。

## 大小核验

- **大小一致**：远端大小与本次发送字节数相同。
- **大小不一致**：不可依赖这份备份。
- **大小未知**：无法判断。
- **无发送基准**：历史文件只能读取大小，不能核对本次发送量。

优先使用 PROPFIND，失败时尝试 HEAD。HEAD 单独返回 0 不认定为空；PROPFIND 明确的 0 保留。只保存最近任务；云端列表仅包含当前目录内符合命名规则的最终 ZIP，最多 200 项，响应上限 2 MiB。

**大小一致不代表 ZIP 内容完整或能够恢复。** 产品不提供下载、删除或恢复接口。

## 备份分类与恢复：前端扩展不是服务端插件

| 类型 | 示例/路径 | 备份与恢复条件 |
| --- | --- | --- |
| 用户前端扩展 | 用户数据下的 `extensions/` | 对应“用户扩展”分类 |
| 全局前端扩展 | `third-party/JS-Slash-Runner/` | 备份与恢复均需选“全局前端扩展”；恢复要求管理员 |
| 服务端插件 | WebDAV 后端等 server plugins | 不在当前 Luker 分类备份中，需要单独安装 |

“全选”不是整个应用目录镜像，不包含 APK、整套运行环境和服务端插件；独立 Skills/CardApp 等覆盖由宿主决定。数据库模式可能包含未勾选分类与 API 密钥。

下载 ZIP 后使用 Luker 的“备份恢复”。**备份时全选，不等于恢复时自动全选。** 恢复界面默认未勾全局前端扩展。`third-party/... -> path_not_in_selected_categories` 表示该路径未进入本次恢复允许范围，不是这条提示就能证明 ZIP 损坏。

对这类提示先确认：

1. 当前是管理员账号。
2. 使用分类“备份恢复”入口，并勾选“全局前端扩展”；只选“用户扩展”不足以恢复它。
3. 比较原生 ZIP 时使用相同导出及恢复分类。原生 ZIP 没有提示，也可能是未导出该分类。

普通 `/import/data-zip` 默认排除全局扩展。不要通过把 `third-party/` 改名塞进其他分类来绕过选择，这可能把文件放错位置。`.git/HEAD` 和 `.editorconfig` 并非此错误码的特殊排除项。

已核对 [Luker edae4ef 的恢复实现](https://github.com/funnycups/Luker/blob/edae4ef84adde5a78c443883c224ef5753f81975/src/endpoints/users-private.js#L279)。当前安装版本可能不同。恢复前保留原数据，在独立测试环境确认分类与结果；源码路径测试不等于完整实际恢复。

ZIP 未加密，应使用私有目录并保护包含 WebDAV 凭据的后端配置。

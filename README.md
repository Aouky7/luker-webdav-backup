# Luker WebDAV 备份

当前版本：**0.5.1**（前端和后端）。

调用 Luker 内置分类备份接口，支持省空间的流式上传和先生成 ZIP 的定长兼容上传。提供云端备份列表、大小查询与最近任务复核；恢复仍使用 Luker 自身功能。

## 安装与更新

仓库：<https://github.com/Aouky7/luker-webdav-backup>

同一仓库需分别安装为服务端插件和前端扩展。更新后重启 Luker 后端、重新加载页面，确认两端均为 **0.5.1**。

手动安装时：

- 后端需要 `index.mjs`、`webdav.mjs`、`staging.mjs`；缺少任一模块会导致加载失败。
- 前端需要 `frontend.js`、`style.css`、`manifest.json`。
- 推荐使用 Git 更新获取完整仓库。运行不需要第三方 npm 依赖；package.json 中的 jsdom 仅供开发测试。
- 新前端遇到旧后端会禁用兼容上传并提示更新，流式模式仍可使用。

接口仅允许当前 Luker 管理员使用。入口名称与备份内容支持范围取决于宿主版本。

## 配置与上传模式

填写最终的 **HTTPS WebDAV 目录地址**、用户名和应用密码（服务商要求时）。当前只支持 Basic 认证，不自动跟随重定向，不关闭 TLS 证书校验。

| 模式 | 行为 | 适用情况 |
| --- | --- | --- |
| 流式上传（默认） | 边生成 ZIP 边上传，不落地完整 ZIP | 服务允许未知长度 PUT，需要节省本地空间 |
| 兼容上传 | 先生成本地 ZIP，取得长度，再从磁盘流式上传 | 服务要求 Content-Length，或希望查看已知总量的上传进度 |

旧配置默认仍是流式模式。两种模式都不会把整个 ZIP 读进内存。兼容模式不能绕过服务端权限、配额、文件大小限制或 MOVE 不支持的问题。

### 兼容模式的本地空间

- 暂存 ZIP 上限默认 **1024 MiB**，可设置为 **64–65536 MiB** 的整数；它是上限，不会预先分配全部空间。
- 后端在系统临时目录的插件专属私有目录暂存，不放进用户备份目录。任务目录权限 0700、ZIP 权限 0600。
- 创建任务及打包过程中检查剩余空间，保留 64 MiB 余量；检查不能排除其他进程同时占用空间，实际磁盘写入失败也会终止任务。
- 本地打包最多 30 分钟，单次上传最多 30 分钟，网络空闲最多 2 分钟。
- 成功、失败或超时后清理本地 ZIP；下次后端启动检查并清理本实例中断残留，不自动续传。清理失败会提示并暂停兼容模式，流式模式仍可用。
- 清理只处理核对过的插件目录和文件，遇到未知内容或符号链接会拒绝删除。每个 DATA_ROOT 应只运行一个 Luker 后端实例。

- 如果 Android/proot 环境报告的系统临时目录（通常是 `/tmp`）不存在，插件会尝试自动创建；系统目录不可用时回退到 DATA_ROOT 的同级私有目录 `.luker-webdav-tmp-*`，不会放入备份数据目录。

### 自动建目录

保存配置只保存设置，不写远端。点击“测试连接”或确认开始备份时，会自动检查目标，创建确认不存在的目标及中间目录，无需额外创建按钮或确认。

需要 PROPFIND 读取属性，缺失目录需要 MKCOL 创建权限。已有目录直接使用；文件路径、权限不足、未知目录状态不会进入上传。最多补建 12 层，总准备时限 60 秒。中途失败可能留下已创建的空目录，不自动删除。

坚果云可填写 `https://dav.jianguoyun.com/dav/LukerBackup/`。直接填写 `/dav/` 根地址时，保存会规范为 `/dav/LukerBackup/`。不会向 `/dav/` 以上探测或创建。

“测试连接”不上传备份，也不验证 PUT/MOVE 权限；完整流程需真实备份验收。

## 日常使用

1. 结束聊天生成和编辑，选好备份分类、上传模式并保存配置。
2. 点击“备份到 WebDAV”，在一个确认框中核对目标、分类和模式。
3. 保持后端运行。兼容模式先显示生成 ZIP 的字节数，再显示已知总量的上传进度；流式模式只显示已发送字节，不虚构百分比。
4. 等待结果，再手动刷新云端列表或复核最近文件大小。

前端进度中的“已发送”是送入上传流的字节数，不代表远端已持久化。两种模式先上传 `.partial`，成功后以 MOVE 改名 `.zip`，最后核对大小。改名返回不明时，最终 ZIP 或 .partial 都可能存在，应检查任务提示。

上传失败不自动换模式或重放写入。遇到 HTTP 411 可选择兼容模式重新开始；413 表示服务或代理大小限制；507 表示云端空间不足。无论哪种模式，都要求服务支持 MOVE。

### 弹窗和任务状态

保存、测试、重新读取、列表与复核有弹窗和面板反馈。备份终态只通知一次；初次打开不反复播报旧任务。大小未知、不一致或本地清理异常显示警告。状态请求失败只表示结果未确认，不代表备份失败。

收起面板仍轮询已观察到的任务；切后台暂停，回到页面恢复。这些是页面内通知，不是系统通知。关闭页面后可重新查看最近任务。

## 大小核验的含义

| 结果 | 含义 |
| --- | --- |
| 大小一致 | 远端大小与本次发送字节数一致 |
| 大小不一致 | 两者不同，不应依赖这份备份 |
| 大小未知 | 未取得可靠大小，无法判断 |
| 已读取大小，无发送基准 | 历史文件缺少本地发送记录 |

优先使用 PROPFIND 的 getcontentlength，失败时尝试 HEAD。仅 HEAD 返回 0 不认定文件为空；PROPFIND 明确的 0 保留为真实值。仅保存最近一次任务，历史文件通常没有发送基准。

**大小一致不等于哈希校验、ZIP CRC 检查或恢复成功。** 日常大小复核不会下载完整 ZIP。云端列表仅显示当前目录内符合本插件命名规则的最终 ZIP；最多显示 200 项，响应最多读取 2 MiB。

## 备份范围与恢复

“全选”是 Luker 原生支持的全部分类，不是整个应用目录镜像。不包含 APK、整套运行环境和服务端插件；独立 Skills/CardApp 等覆盖范围取决于宿主版本。

用户扩展和全局前端扩展是不同分类。已检查的样本中，全局扩展位于 ZIP 根级 `third-party/`；不能因为 `extensions/` 为空就认定漏备份。数据库模式可能包含未勾选分类和 API 密钥。

ZIP 未加密，后端配置也包含 WebDAV 凭据，应使用私有目录并保护后端数据目录。

从网盘下载 ZIP 后，使用 Luker 自身备份恢复功能。按核对过的 [Luker 恢复源码](https://github.com/funnycups/Luker/blob/release/src/endpoints/users-private.js)：

- 分类恢复 `/restore-backup` 可恢复全局扩展，需要管理员并选中全局扩展分类。
- 普通 `/import/data-zip` 会关闭全局扩展恢复，不能替代上述入口。
- 恢复器识别根级 `third-party/` 并映射到扩展目录，无需手动改 ZIP。

核对自己安装版本的能力，恢复前保留原数据，检查合并/覆盖模式和恢复结果。插件没有自建恢复、下载或删除接口。

其他酒馆不能据此认定完整兼容。例如已检查的 [TauriTavern 导入实现](https://github.com/Darkatse/TauriTavern/blob/85dc99089e3fcc9d3a0aafc085564bd642895261/src-tauri/crates/tt-adapter-archive/src/data_archive/import/extract.rs) 不会把这种根级 `third-party/` 自动映射到全局扩展。

## 开发测试

Node.js 22：

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run test:network
```

`npm test` 包括目录、XML、大小、路由、暂存生命周期、上传故障及 jsdom 前端回归。网络测试临时生成证书并通过测试子进程信任；生产 TLS 不变。GitHub Actions 分别运行普通回归与独立服务端互操作。

独立服务端的固定版本、Python 安装命令、参考项目提交和新增服务验收清单见 [兼容性记录](COMPATIBILITY.md)。运行时无 npm 第三方依赖；安装测试依赖只用于开发和 CI。

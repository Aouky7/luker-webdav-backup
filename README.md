# Luker WebDAV 备份

当前版本：**0.4.0**（前端和后端）。

调用 Luker 内置分类备份接口，边生成 ZIP 边上传到 WebDAV，不先在本地创建完整 ZIP。支持查看云端备份列表、查询文件大小和复核最近一次上传。插件不提供恢复、下载或删除备份操作。

## 安装与更新

仓库链接：<https://github.com/Aouky7/luker-webdav-backup>

同一个链接需要分别安装两次：

1. 在 Luker 的服务端插件管理中安装后端，然后重启 Luker 后端。
2. 在扩展管理中安装前端，完成后重新加载页面。
3. 打开扩展列表中的 **WebDAV 备份**，确认前端和后端版本。

更新时也需要分别更新两端，再重启后端、重新加载页面。插件接口仅允许管理员使用；实际入口名称可能随 Luker 版本变化。

手动更新时，后端必须同时包含 `index.mjs`、`webdav.mjs`；前端必须同时包含 `frontend.js`、`style.css`、`manifest.json`。缺少 `webdav.mjs` 会导致后端启动失败，缺少 `style.css` 会导致面板样式异常。推荐通过软件的 Git 更新功能获取完整仓库。

## WebDAV 配置

需要提供 HTTPS 目录地址、用户名和密码（服务商要求时使用应用密码）。保存配置只保存设置；点击 **测试连接** 或确认开始备份时，插件会自动检查目录，并创建确认不存在的目标及中间目录，无需单独点击创建或去网盘手动建目录。

自动创建需要服务支持 MKCOL 并赋予账号创建权限。已有目录直接使用；路径为文件、权限不足、响应无法识别时不会继续创建或上传。创建前会找到可用的父目录，最多补建 12 层，总准备时限 60 秒。不会创建服务器根目录，坚果云不会向 `/dav/` 以上探测或创建。中途失败可能留下已创建的空目录，不会自动删除。

服务需要支持：

- `PROPFIND`：读取目录和文件属性。
- `MKCOL`：自动创建缺失目录；已有可用目录不需要此权限。
- `PUT`：接受未知总长度的流式上传。
- `MOVE`：将上传完成的临时文件改名。
- `HEAD`：属性查询不可用时尝试查询大小。

不限于坚果云，但其他服务仍需实际验证这些能力。要求上传前提供固定 Content-Length 的服务可能不兼容当前上传方式。

坚果云可填写 `https://dav.jianguoyun.com/dav/LukerBackup/`，使用自己的账号与第三方应用密码；直接填写 `https://dav.jianguoyun.com/dav/` 时，保存会自动改为 `/dav/LukerBackup/` 并在反馈中说明。测试连接或备份时尝试自动创建，不向 `/dav/` 根目录直接上传 ZIP。若服务拒绝创建顶层文件夹，会显示明确错误及手动创建的备用方案；插件不能绕过服务商的权限限制。

保存配置后点击 **测试连接**。这个操作会读取目录并在缺失时写入目录，不上传备份文件，也不证明 PUT/MOVE 权限；首次真实备份才能验证完整上传流程。

## 日常使用

1. 结束聊天生成和编辑，选择需要备份的分类并保存配置。
2. 点击 **备份到 WebDAV**，核对目标目录和分类后确认上传。
3. 保持 Luker 后端运行，等待最近任务结束。关闭面板不会取消后端任务，但 Android 结束后端进程会中断任务。
4. 点击 **刷新云端列表** 查看已有备份，或使用 **重新检查大小** 复核最近一次上传。

### 操作反馈

保存配置、测试连接、手动重新读取、刷新列表和大小复核会显示成功或失败的弹出提示，并保留面板文字。优先使用 Luker 自带的轻量通知；宿主未提供时使用文字弹窗。不会把通知内容作为 HTML 执行。

备份启动后显示准备提示；本页观察到任务完成时只提示一次。大小一致显示成功，大小异常或未知显示警告，任务失败或中断显示错误。网络导致状态读取失败只提示“结果尚未确认”，不会冒称备份失败。首次打开面板不会反复播报旧任务结果。

收起面板后，只要页面仍可见就继续轮询已观察的任务；切后台时停止轮询，回到页面继续检查。这是页面内提示，不是 Android 系统通知；关闭或重新加载页面可能无法补报此前完成的任务，应查看最近任务记录。

上传先写入 `.partial` 文件，成功后改名为 `.zip`。失败或中断可能留下 `.partial`，不要将其当作有效备份。若已改名后任务意外中断，也应单独核验最终 ZIP。

### 大小检查的含义

| 结果 | 含义 |
| --- | --- |
| 大小一致 | 远端大小与本地记录的发送字节数一致 |
| 大小不一致 | 两者不同，需要进一步检查，不应依赖这份备份 |
| 大小未知 | 未取得可靠的远端大小，不能判断是否一致 |
| 已读取大小，无发送基准 | 查询到了历史文件大小，但缺少该文件的本地对照记录 |

优先读取 `PROPFIND` 的 `getcontentlength`。属性查询不可用时尝试 `HEAD`；只有 HEAD 返回 0 时不会直接认定文件为空。PROPFIND 明确返回 0 则保留真实的零字节结果。

仅保存最近一次任务记录。历史文件通常没有发送基准；最近任务的文件名与目标目录仍匹配时，复核结果会更新任务状态。

**大小一致不是内容哈希校验、ZIP CRC 检查或恢复测试。** 插件不会为大小复核下载整个 ZIP。

## 备份范围与限制

“全选”指选中 Luker 原生支持的全部分类，**不是整个应用数据目录镜像**。具体覆盖范围由所安装的 Luker 版本决定。服务端插件、APK 和整套运行环境不在这些分类内；独立 Skills、CardApp 等内容也不能仅凭分类名称推定已经包含。

- 用户扩展与全局前端扩展是不同分类。ZIP 中的 `extensions/` 可以为空，而全局扩展保存在 `third-party/`；应检查整个 ZIP，不能仅凭空的用户扩展目录判断漏备份。
- ZIP 内路径由 Luker 归档接口决定。实测样本中，插件与 Luker 自带导出均使用根级 `third-party/`。
- 数据库模式可能导出分类之外的数据和机密，即使没有勾选 API 密钥。文件模式与数据库模式的恢复需要宿主相应支持。
- ZIP 未加密。使用私有目录，勿公开备份、密钥、应用密码或含敏感信息的配置文件。后端配置包含连接凭据，应保护其数据目录。
- 云端列表只包含当前目录内、符合本插件命名规则的最终 ZIP，不显示子目录、`.partial` 或其他软件的备份。
- 单次响应最多读取 2 MiB，超限报错；列表最多返回 200 项，超过时提示。服务端自身也可能限制返回数量。

## 恢复与迁移

从 WebDAV 下载 ZIP 后，使用 **Luker 自身的备份恢复功能**。本插件不改变导出内容，也不执行恢复。

按核对时的 Luker release 源码：

- 支持分类选择的 `/restore-backup` 入口可恢复全局扩展，但要求管理员身份并选中全局扩展分类。
- 普通 `/import/data-zip` 入口关闭全局扩展恢复，不能用它替代全局扩展还原。
- 恢复器识别根级 `third-party/`，可映射至当前配置的全局扩展目录，无需手动改 ZIP。

请核对安装版本实际具备这些能力；备份时全选不代表恢复时自动全选。恢复前保留现有数据，并检查合并或覆盖模式。恢复后查看成功、失败、跳过和拒绝数量，再确认角色、聊天、世界书和扩展是否正常。

源码参考：[Luker 恢复接口](https://github.com/funnycups/Luker/blob/release/src/endpoints/users-private.js)、[分类导出接口](https://github.com/funnycups/Luker/blob/release/src/users.js)。这些分支会变化，源码说明不能替代所安装版本的恢复验收。

其他酒馆软件可能兼容角色和聊天，但不兼容完整归档路径。例如核对过的 TauriTavern 导入逻辑不会将这类用户备份中的根级 `third-party/` 自动映射为全局扩展；不要因为部分数据导入成功就认定完整恢复。参见 [TT 路径转换实现](https://github.com/Darkatse/TauriTavern/blob/85dc99089e3fcc9d3a0aafc085564bd642895261/src-tauri/crates/tt-adapter-archive/src/data_archive/import/extract.rs)。

## 验证记录

0.3.0 已有用户实测坚果云上传后的大小复核和云端列表，手机截图确认新版分区样式生效。

另对一组先后生成的插件备份与 Luker 自带备份进行了离线比较：

- 两份 ZIP 全部条目通过读取、解压及 CRC 检查。
- 全部备份分类均已勾选，2,425 个共有文件的 SHA-256 一致。
- 11 个第三方扩展目录、2,203 个扩展文件的路径与内容全部一致。
- 两个共有文件有变化：清单的生成时间，以及设置文件中的扩展设置。较早的插件备份另多一个预设文件。
- 该组样本没有发现插件相对原生备份额外漏项；两次生成时间不同，不能将全部差异归因于导出方式。

这些结果不是所有版本、所有服务商的兼容保证，也不是已完成实际 Luker 恢复测试的声明。用户 ZIP、密钥和聊天内容不随测试发布。

## 开发测试

使用 Node.js 22，从仓库根目录运行，无需安装 npm 依赖：

```sh
node --check index.mjs
node --check webdav.mjs
node --input-type=module --check < frontend.js
node --test tests/*.test.mjs
```

最后一个语法检查按浏览器 ES 模块处理前端代码。GitHub Actions 对推送、拉取请求和手动运行执行同样的检查。

- `tests/webdav.test.mjs`：八个属性解析、大小判断与目录范围回归测试。
- `tests/backend.test.mjs`：一个模拟 HTTPS 和宿主模块的路由集成测试，包含管理员检查、XML 请求长度、列表、复核持久化、非法名称拒绝和响应上限。
- `tests/directory.test.mjs`：八个自动创建目录测试，覆盖已有目录、缺失层级、资源级 404、非目录、权限拒绝、创建冲突、未知结果、根目录边界与时限。
- `tests/directory-routes.test.mjs`：一个路由集成测试，覆盖保存不写云端、坚果云根地址规范化、测试与备份自动建目录、并发锁，以及准备失败不上传用户数据。

0.4.0 的自动建目录和通知逻辑已在模拟请求与前端 DOM 环境验证；尚未用真实网盘账号验证 MKCOL 或在手机上验收新增弹出效果。0.3.0 的实测记录不等于本版新增功能已经实测。

测试使用合成数据和临时目录，不需要真实账号、不连接网盘、不执行恢复。路由测试结束会还原进程状态并清理本次创建的临时目录。这些测试不覆盖真实宿主恢复、前端渲染或扩展运行兼容性。
